# react-folding-fan-gallery

A React component that arranges cards in an interactive folding-fan arc. Hover or focus any card to bring it to the front — the surrounding cards shift scale and z-order to stay out of the way.
It's great for photo galleries, product showcases, restaurants or any situation where you want to display a small number of items in a visually appealing way.

<Story of={GalleryStories.FiveCardsDemo} />

## Installation

```sh
npm install react-folding-fan-gallery
```

## Basic usage
You can quickly start with a builtin card element, but it is recommended to create you own (spark the creativity! ✨) and pass it to the `renderer` prop.

```tsx
import { Gallery, Card } from 'react-folding-fan-gallery';

const photos = [
  { image: '/img/a.jpg', alt: 'Mountain' },
  { image: '/img/b.jpg', alt: 'Forest' },
  { image: '/img/c.jpg', alt: 'Lake' },
];

// cards.length must be odd
<Gallery
  cards={photos}
  renderer={(item) => ( <Card {...item} /> )}
/>
```

> **Requirement:** `cards` must always contain an **odd** number of items so the fan has an unambiguous center card.

## How it works

Cards are placed along an invisible arc defined by a virtual circle. Each card's `left`, `top`, `rotation`, and `scale` are calculated using CSS trigonometry. When a card is hovered or focused, the active card's scale is increased and its z-index is raised above the others, while the surrounding cards are scaled down.

All positional updates bypass React's render cycle: a single `useLayoutEffect` writes CSS custom properties directly onto a shared container `div`, which inherited variables pick up automatically. Individual `CardWrapper` components are wrapped in `React.memo` and only re-render when their active state changes - hover on any card triggers rerender only on that one card.

### Anchor height

`anchorHeight` controls where on the card the rotation pivot sits. Think of it as the point where an invisible pin holds the card and rotationAngle rotates it.

- **Small value (e.g. `'5%'`)** — the pivot is near the top of the card. Cards fan out from their tops, like playing cards fanned in a hand. The visible gap between cards is narrow at the top.
- **Larger value (e.g. `'40%'`)** — the pivot is closer to the card's center. Cards spread more evenly and the fan opens further at the top.

You can use `%`, `px`, or `rem` unit for `anchorHeight`.

### Renderer

The `renderer` function is also called **once with `undefined`** during initialization so the gallery can measure the rendered card's dimensions off-screen. Make sure the output has a consistent, data-independent size:

```tsx
// ✅ Fixed size — measurement is reliable
renderer={(item) => (
  <div style={{ width: 120, height: 160 }}>
    {item?.title}
  </div>
)}

// ⚠️ Variable size — measurement may not match actual cards
renderer={(item) => (
  <div>{item?.longDescription}</div>
)}
```

## Dynamic bounding box

By default (`overflowTop: true`, `overflowBottom: true`) the gallery root container has a fixed height equal to the initial cards layout (top of the center card and lowest corner of the edge card). When cards are active they may overflow the container.

Setting `overflowTop` or `overflowBottom` to `false` triggers a geometric calculation that traces every corner of every card — accounting for its exact position, rotation angle, and scale — and sizes the container to contain them all. This is useful in page layouts where you need the gallery to coexist with surrounding content without overlapping it.

In the examples below the **red border** marks the edge of the gallery root element.

### Bottom only (`overflowBottom: false`)

The container height grows to contain the lowest corner of every card. Cards may still extend above the top edge.

### Top only (`overflowTop: false`)

## Accessibility

Every card renders as a `role="button"` element with `tabIndex={0}` and `aria-pressed` reflecting its active state. Keyboard users can navigate between cards with `Tab` and activate a card with `Enter` or `Space`, triggering the same hover effect as a mouse.
